# Fast compilation implementation plan

Design: [architecture and contracts](../specs/2026-10-17-fast-compilation-design.md). Evidence: [current measurements and reproduction](../../reviews/fast-compilation/README.md). Baseline: `39dc2f6`. Tasks below are implemented; the [implementation record](../../reviews/fast-compilation/implementation/README.md) contains validation, final measurements, explicit target misses and the dated prototype-rollout exception. Original thresholds remain unchanged.

## Delivery order and ownership

Use one coordinator for checker/selection/coordinator changes. After the checked-artifact and bounded-loop interfaces are reviewed, independent owners can implement C and Wasm lowering in parallel. A reviewer who did not write each trust-boundary change must inspect it before integration. Run performance qualification serially, with no concurrent benchmark jobs.

| Task | Depends on | Reviewable result |
| --- | --- | --- |
| 1. Measurement contract | Baseline | Reproducible phase/count/size evidence |
| 2. Owned compilation context | 1 | Fresh public admission; internal proof handoff |
| 3. Ranked policy | 2 | One ordinary successful proof; explicit search status |
| 4. Bounded loop correspondence | 2 | Exact expansion validation, no new eligibility |
| 5. Compact C | 4 | Small C plus real native correspondence |
| 6. Compact Wasm | 4 | Small module/local count plus real-engine correspondence |
| 7. Integration and qualification | 3, 5, 6 | Verified browser/native release candidate |
| 8. Residual-cost decision | 7 | Measured next experiment or stop |

Do tasks 2 and 3 before spending time on source DAG interning. Do not start a new native backend before compact C is measured. Tasks 5 and 6 may run in parallel, but benchmark runs must not.

## 1. Freeze boundaries and establish phase instrumentation

Files: extend `tools/compare-playground.py`; add `tools/profile-compilation.py` and a research-only browser harness under `tools/benchmarks/`; document the phase schema in `axiom/docs/playground.md`. Use the retained diagnostic probes as a starting point, not a release benchmark.

1. Define timed fields: source admission, candidate generation, structural validation, semantic checking, canonical encoding, internal decode, loop correspondence, code emission, native compiler/link, Wasm compile/instantiate, first execution, verification, total fresh-source preparation and total app boot. Include counts, candidate state, bytes/locals, flags and identity fields. Keep nested/inclusive fields labeled.
2. Add a measurement hook or trace sink with negligible disabled overhead; avoid global mutable monkeypatching in production. Quota/work receipts remain deterministic and separate from wall time. Tests should assert phase/count identities rather than unstable milliseconds.
3. Build baseline fixtures for 1×1, 5×7, 15×15, 1×127, 127×1, odd/even cases, both objectives and caps immediately below/equal/above each schedule's reservation. Include source-only comment/rename edits, cap/objective edits and changed input-only runs.
4. Record source-fresh/runtime-ready and engine-cold cases separately. Repeated source nonces may produce identical Wasm; disclose engine code reuse. For key engine-cold qualification samples use a fresh browser process with a fresh temporary profile and Worker, or verified engine-cache control. A fresh Worker alone is insufficient. Load runtime/imports before timing the first user program and retain boot separately; do not warm up that program.
5. Retain clean revisions, raw samples, source/plan/module/compiler hashes and independent observation audits. Reuse the paired baseline/candidate pattern, not an unrelated older screenshot.

Acceptance: reproduce baseline counts and generated bytes; no production behavior change. Preserve previous execution benchmark scope and visible compilation fields.

## 2. One admission context and owned checker handoff

Files: new `axiom/src/axiom/compilation.py`; refactor `checker.py`, `codec.py`, `selection.py`, `runtime.py`, `wasm.py`, `native_codegen.py`, `playground_service.py`. Add `axiom/tests/test_compilation.py`; extend existing checker/codec/service/backend tests.

1. Extract internal fresh source admission and immutable candidate validation/encoding ownership. Public functions keep their signatures and fresh admission. Limits and caps must be exact validated records, not caller-forged context metadata.
2. Extract the semantic portion of `check_plan` so a compilation-owned candidate can be checked without reparsing raw source or structurally walking it again. Preserve every physical operation, expression grouping, interval check, partial receipt, diagnostic order and accounting-v1 cutpoint. Public `check_plan` still admits/validates before entering it.
3. Add a private legacy compilation selector using the existing portfolio order and fallback/budget contract, with an owned successful result. Share implementation where it avoids divergent semantics; do not have two independently evolving search algorithms accidentally claiming the same policy.
4. Make internal emitters consume the owned successful result. Keep public byte APIs routed through fresh checking. Remove internal selected-plan JSON encode/decode round-trip; reuse already generated canonical bytes for reports/export and distinguish raw versus canonical identity on external calls.
5. Preserve emitted C/Wasm byte for byte. The coordinator clears old preparation before any new-source attempt; no partially admitted state becomes executable.
6. Tests: unchanged public forged-record/cap/dead-overflow rejection; source/plan/limit substitution; original-byte versus canonical digest; unchanged deterministic receipts under legacy selection; one admission and no backend recheck on the owned path; public backend calls still check afresh; artifact lifetime and failure/cancellation invalidation.

Targeted verification from `axiom/`:

```sh
PYTHONPATH=src AXIOM_TEST_NATIVE_CLANG=/path/to/clang python -m unittest \
  tests.test_compilation tests.test_checker tests.test_codec tests.test_selection \
  tests.test_runtime tests.test_native_codegen tests.test_wasm tests.test_playground_service
```

Set the real available compiler path; do not count skipped native tests as native validation. Acceptance: byte-identical outputs and legacy receipts; internal decode=0 and backend semantic recheck=0, with no >10% small-case regression in paired measurements.

## 3. Separate ranked-proof search policy

Files: `compilation.py`, `selection.py` or new `compilation_selection.py`, `codec.py`, `playground_service.py`; tests in `test_compilation_selection.py`, `test_selection.py`, `test_playground_service.py`.

1. Freeze policy identifier, attempt states, stop reasons, policy digest, `portfolio_optimal` meaning and shared-budget charging rules from the design. Keep `select_plan` legacy behavior, including `optional_check_steps=0` and incumbent-on-later-error, intact.
2. During validation collect actual multiplication count, operation count and exact declared scratch reservation. Only these complete actual-stream metrics rank/filter candidates. Compare them with the eventual eligible receipt before handing off.
3. Generate/validate the full fixed portfolio, filter conclusive structural/cap failures, stable-sort the exact existing key and prove in order. On first success emit the checked winner. On conclusive invalidity try the next. On unknown/generation error/checker exception/cancellation stop without a new artifact; never reset allowance or invent checks for skipped candidates.
4. Exhaustively compare complete-budget winners and canonical bytes with legacy selection across all 955 admitted shapes and the existing 14,518 cap/objective contexts. Add identical-key stable ties, misleading/renamed labels, corrupted metrics, structurally valid wrong arithmetic and malformed candidates.
5. Exercise budget prefixes around the first successful proof, including zero/one step and source-expression quota boundaries; assert unknown cannot produce an optimality claim. Verify exception charging without a receipt and cancellation at every stage.
6. Add report policy/state fields under a versioned contract. Avoid breaking legacy schema silently: use a new compiled-policy report version while retaining the legacy interpreter report. Public UI may say why a candidate was not checked, but must not fabricate semantic eligibility.

Acceptance: independently review the ordering argument and every terminal state. Ordinary canonical examples require one complete proof; complete-budget winners/metrics remain identical. Do not claim a wall-time factor until measured.

## 4. Bounded structured program and independent correspondence

Files: new `bounded_loop_model.py`, `bounded_loop_codec.py`, `bounded_loop_correspondence.py`, optional `bounded_loop_planner.py`; retain `planner.py` public v1 output. Tests: corresponding `test_bounded_loop_*.py`, frozen expansion corpus.

1. Freeze a small internal format distinct from scalable loop v2. Start with bounds fixed by admitted v1 dimensions, unit-step lexical loops, existing primitives, bounded affine indices and explicit modulo two. No conditionals, general reductions or loop-carried scalar SSA are necessary for the current three schedules.
2. Define explicit new hint-processing ceilings without raising v1 limits: suggested starting ceilings are 64 KiB encoded hint, 4,096 syntax nodes, nesting depth 16, 100,000 charged traversal/index/SSA steps and expanded operations no greater than the existing `plan_operations` limit. Bound each loop/control visit and iteration, including empty bodies and zero-trip inner loops. Precompute a saturating traversal-cost bound before entering nested expansion and enforce per-step charging too. Review exact-integer/index intermediate bounds and enforce limits before recursion/allocation; reject bool-as-int and oversized coefficients/bounds. Final constants require measured fit, not an assumption that syntax/op limits bound empty traversal.
3. Generate finite and structured representations from the same untrusted scheduling intent. Correspondence validation must be independent of the generator, so a shared generator bug cannot certify itself.
4. Expand with fresh dense SSA identities per iteration and compare the complete actual stream, reservation and source specialization. Preserve v1 hoisted constant and two-row stage/consume/refill order. Compare metadata only for required bounded-format validity; it is never proof authority. Bind original finite-plan identity and exact structured bytes in the internal result.
5. For every admitted shape and schedule, compare expansion against frozen current v1 fixtures. Avoid regenerating both expected and actual with the new implementation in the same assertion. A compact hint grants no eligibility without a complete finite check.
6. Adversarial tests: changed/negative/overflowing index intermediates, wrong parity, off-by-one bounds, alias/scoping escapes, omitted/duplicated/dead/suffix operations, shifted operand grouping, larger scratch capacity, hostile expansion sizes and recursion, deeply nested empty bodies and zero-trip leaves under many-trip outer loops. Assert bounded rejection and typed hint-work exhaustion/fallback. Valid changed plan labels must not be rejected solely for the label.
7. Any valid finite plan without a successful compact correspondence uses existing emission; record fallback reason. Structural/hint quota failure never weakens source/plan/proof quotas or resets semantic work.

Acceptance: independent model/decoder/expander review, complete expansion corpus, exact operation/identity binding and no new scalable-proof claim. Existing v2 F1 remains blocked.

## 5. Compact C lowering

Files: `native_codegen.py`, optional private `bounded_loop_c.py`; `test_native_codegen.py` and new compact tests; `tools/compare-playground.py` for sizes/compiler phases.

1. Emit lexical loops and local variables from the validated structured program, retaining each primitive's order/grouping and int64-first checked-i32 lowering. Do not emit a formula based on a recognized plan ID.
2. Preserve row-major full input preflight, first invalid status, unchanged initialized destination on rejection, exact dimensions/driver token handling and disjoint pointer ownership. Check emitted index arithmetic and loop counter bounds, not only final normalized addresses.
3. Exercise inline/materialize/rows2 on boundary shapes, repeated changing inputs, scratch poison/canaries, output sentinels, multiple invalid inputs and valid arbitrary finite-plan fallback. Compare full callable-kernel observations with original AST and finite interpreter; execute the standalone driver's malformed-input cases too.
4. Add rehashed faulty emitters that omit a store, change an index or refill rows early; independent execution checks must catch them. Test that an eligible receipt for another exact plan/context cannot enter compact emission.
5. Compare generated C bytes, Clang frontend/optimizer/codegen trace, optimized IR/object bytes and complete link time. Compilers may re-unroll fixed loops. Evaluate optimization/unroll policy only as an explicitly identified experiment, including kernel throughput; keep current default until evidence supports change.

Acceptance: ≥10× source-size reduction target at 15×15, unchanged full behavior and paired cold-build improvement. A size reduction alone does not satisfy the latency gate.

## 6. Compact Wasm lowering

Files: `wasm.py`, optional private `bounded_loop_wasm.py`; `test_wasm.py`, compact tests and real-browser harness.

1. Emit structured `block/loop/br` control and bounded local reuse from validated lexical scopes. Handle label depths, signed comparisons, loop limits, modulo/index evaluation and byte-address overflow explicitly. Preserve import-free fixed memory and exported ABI.
2. Emit preflight as a loop before body effects. Keep complete failure-state preservation and memory regions disjoint; reused instances cannot rely on scratch contents left by earlier calls.
3. Execute real Node/V8 modules, then actual Chromium under the shipped CSP. Compare complete state with both independent source evaluation and the finite interpreter for all schedules and boundary shapes. Include changing inputs across many artifact reuses and multiple invalid cells.
4. Add malformed/correspondence-mismatch hints, wrong loop branch/operand/index/store mutations and hostile local/syntax/expansion sizes. Validate resulting bytes with a real engine; a module hash does not establish correctness.
5. Measure module bytes/local count, Python emission, JS compile/instantiate and first-call time separately. Native machine-code compilation may be lazy or cached by the engine; retain those limitations.

Acceptance: ≥10× bytes/local reduction target at 15×15, unchanged full observations and real-browser behavior. No larger shape or new language feature is admitted.

## 7. Integrate, review and qualify the release candidate

Files: `playground_service.py`, `playground_web/worker.js`, `transport.js`, `app.js`, browser tests; `tools/build-playground-site.py`, `test_playground_site.py`; docs/evidence.

1. Coordinate new compilation transaction, ranked report policy and compact artifacts. Clear stale preparation before work, install only complete current-source artifacts, retain cancellation/reset semantics and show original compilation cost after reuse. Input-only edits must reuse the exact prepared source without weakening scalar validation.
2. Update UI state wording only where the changed search report requires it. Keep benchmarks readable and scope labels precise. Preserve original-AST independent verification on every observed request.
3. Review the exact public module allowlist and standalone import closure for any new bounded dependencies. Nothing from scalable v2, Core bindings, recovery/session records or private research enters the release. Retain MIT and current public branding rules.
4. Run final appropriate complete suites once integration stabilizes:

```sh
cd axiom
PYTHONPATH=src AXIOM_TEST_NATIVE_CLANG=/path/to/clang python -m unittest discover -s tests -v
```

From repository root run `node tools/test-playground-ui.cjs`, build the static site with `python3 tools/build-playground-site.py --output /tmp/beryl-fast-site`, and run the existing standalone ZIP/site tests plus actual Chromium cold/reused-source, cap/objective/input, invalid-boundary, reset/cancellation and benchmark-table checks. Run research tests if shared interfaces were changed; do not reinterpret their success as v2 qualification.

5. Qualify serial baseline/candidate on a fixed host: at least 21 samples for key cold cases, changing nonconstant inputs, explicit infrastructure warmup policy, separate first-call costs, paired C/Rust builds and independently audited results. Add a high-iteration callable-kernel throughput harness so process startup cannot hide a regression. Prevent input/result hoisting using changing buffers and observable consumed outputs; retain audit outside timing.
6. Require the design's browser/native targets, no correctness/constraint/accounting regression, and no >10% prepared/actual-kernel throughput regression. Report median/p95/raw samples, misses and variance. Re-run only where changed code, failures or unresolved concerns justify it.
7. Independent reviews: ownership/accounting; ranking/status/versioning; loop correspondence and numeric/memory semantics; C/Wasm actual emission; benchmark/public export. Fix material findings before publication. Retain compiler/plan/loop/artifact hashes and clean commit references.
8. Prepare private PRs and a concrete reviewed public release under the existing bounded MIT authorization. Publish only after gates pass; verify live asset hashes and real-browser results. Keep the old valid backend/release as rollback. Attach created PRs to the task.

## 8. Decide residual work from measurements

If targets pass, stop this latency milestone and document results. If not, choose one experiment according to the residual:

- Source checking dominates: request-local DAG/fact sharing with preserved virtual accounting, or explicitly versioned accounting if preservation is infeasible. Exhaustive budget-prefix/forged-record tests are required.
- Clang dominates: compact-code optimization policy, strict host-runtime split, then a bounded native baseline/stencil backend feasibility comparison. Include installation/runtime infrastructure costs and kernel throughput.
- Browser Python/bridge dominates despite reduced work: evaluate moving only the measured bounded checker/frontend hot path to a smaller compiled component, with differential semantics/accounting and package-size tests; do not default to a compiler rewrite without data.
- Remaining app startup dominates: treat Pyodide download/boot as a separate product milestone with its own cold-network scope.

Symbolic shape-independent proof is its own research track, requiring closure of F1 with a complete certificate, actual decoder/checker coverage and independent charged-work review before subsequent scalable production gates. The bounded compact path is useful without changing that status.
