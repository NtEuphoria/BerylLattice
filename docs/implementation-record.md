# Axiom prototype implementation record

Implementation date: 2026-10-16 UTC. This records the three approved implementation
plans: correctness prototype, Core bridge and correspondence, and research
evidence infrastructure. Axiom remains Lattice's experimental 5GL; Core remains
the separate Beryl 4GL. The implementation uses Python 3.12+ and the standard
library. This is a bounded executable research prototype, not a language release
or a performance result.

## Delivered boundaries

| Component | Implemented behavior | Boundary |
| --- | --- | --- |
| Source language | Original source AST, byte spans, profile admission and independent evaluation | One two-stage stencil; positive H/W; at most 256 input cells; checked i32; input values 0..1023 |
| Plans and checking | Three physical schedules, strict versioned codecs, independent symbolic/storage/range checking | Unsupported symbolic forms remain unknown; scratch arena capacity excludes SSA temporaries and native memory |
| Selection and replay | Explicit work budgets, deterministic ranking, coherent incumbent, immutable artifacts, fresh exact replay | No saved success bypasses current checking or constraints |
| Core bridge | Qualified pinned compiler, fixed-case source emission, complete observations, isolated supervised execution and capsules | Empirical correspondence for explicit cases; no general native ABI or large-buffer lowering |
| Research evidence | Streaming complete state, frozen experiment and chronology, receipt consistency, independent synthetic oracle binding, evaluator adapter | Native admission is always unavailable; synthetic infrastructure results cannot establish a speedup |
| Cloud setup | Minimal portable startup and optional signed-package bootstrap/native qualification | Existing image dependencies and retained absolute paths remain explicit assumptions |

## Implementation rulings and revision costs

These are the controller's recorded resolutions of implementation ambiguities.
They preserve the approved bounded contract; changing them requires the costs
stated here.

1. **Shape names:** alpha-renamed height/width names retain their ordered
   declaration roles. Supporting reordered declarations requires a versioned
   admission rule and additional tests.
2. **Codec limits:** encoding and digest APIs accept the same explicit `Limits`
   as checking. Narrowing this API would need a format-compatible migration.
3. **Origins:** origin IDs are original AST UTF-8 byte offsets. A separate
   origin table would require a provenance version and mapping migration.
4. **Overwrite control:** the negative control overwrites a still-live scratch
   cell; overwriting a retired cell can be equivalent. Changes to liveness
   require regenerating and independently evaluating the control.
5. **Selection enumeration:** actual checking covers every admitted shape;
   additional cap/objective contexts reuse test-only verified semantics because
   those contexts do not change the symbolic body. A context-sensitive checker
   defect would require expanding fresh combined checks for that context.
6. **Interrupted checker accounting:** an interrupted call without a work
   receipt consumes its full assigned allowance. This can overcharge unused
   work; recovering it requires an explicit progress-receipt contract.
7. **Search exhaustion:** a later step exhaustion stops optional search and
   retains the checked incumbent. Trying later candidates after such exhaustion
   would require a versioned continuation policy and additional tests.
8. **Linux math linkage:** external `clang.cfg` supplies `-lm`, which the pinned
   Core build scripts omit. It is part of the toolchain identity; a revised
   configuration requires rebuilding and requalifying the toolchain.
9. **Existing Core failures:** the two exact baseline failures remain visible
   while correspondence is qualified independently. If they affect emission,
   the affected lane must stop and the adapter be revised; the exception cannot
   become a semantic pass or a silent skip.
10. **Witness Core selection:** `--core` names the pinned source checkout for an
    isolated build with provenance. Prebuilt compiler selection would require
    an explicit qualified-toolchain option.
11. **Capsule publication:** execution uses a private retained working directory;
    export uses pinned directory descriptors. Original runtime paths remain
    required and copies consume additional disk. Moving a qualified capsule
    needs a separately defined relocation contract.
12. **Synthetic held-out coverage:** the approved W8191/H1/seed65537 stratum
    exercises descriptive `synthetic_gate_pass` with independently authored test
    expectations. A wrong fixture must be corrected; it provides no native or
    scalable-oracle inference. The frozen primary stays W2047/H2049/seed65537.

Other concrete choices are documented at their interface: bounded plan labels
and integer tokens, canonical exact replay, row-major first-failure indices,
semantic/acquisition separation, explicit `Objective` enums, no native enable
flag, and externally selected synthetic oracle pins. Test tracing observes the
original evaluator without introducing a test-only product callback. Root
serializes local commits; generated receipts remain outside tracked source.

## Remaining research gates

The delivered plans intentionally do not implement larger native buffers,
loop-plan v2, a reviewed physical collector, or a scalable independent source
oracle. Native performance admission remains unavailable until those contracts,
implementations and reviews exist. No speedup, general equivalence theorem,
full transitive toolchain identity, hostile same-UID storage isolation, or
automatic adoption follows from these results.

Nightly correspondence is opt-in and is not counted as executed here. The
mandatory corpus and fault controls are the acceptance evidence. Local commits
and saved environment drafts are not publication; fresh-task restoration of
local-only revisions has not been established.
