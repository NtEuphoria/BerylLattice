Every FBGEMM time has its ~20 µs Python call cost subtracted.

Where beryl ties or still loses

  • On one thread, the big layer is a tie, not a win.
  • With full-range int8 weights, inputs above 127 get no fast path: 690 µs (inputs to 255) against 327 µs.
  • FBGEMM also turns its output back into 8 bits; beryl's kernel stops at 32-bit sums.
  • beryl's pair rule and its C step are tested, not yet proved.
Not like for like: beryl checks every input and returns int32; FBGEMM checks none, requantizes to u8 and uses its own weight layout. PyTorch 2.15.0+cpu, torch.ops.quantized.linear with prepacked weights. beryl's C built with gcc -O3 -march=native in WSL.
